# DM4310 云台：从反馈记录到动力学辨识

[文档导航](README.md) · [测试数据清单](TEST_DATA.md) · [电机适配](MOTOR_PROTOCOL.md)

DM4310 可以沿用本库的积分辨识方法：先核对 MIT 反馈和力矩比例，再用固定底座、固定构形的独立日志辨识，最后评估是否在 STM32 上启用在线估计。**能够解码力矩报文，不等于已经获得标定后的实际关节力矩。** 本仓库目前没有 DM4310 云台的实机辨识结果；工程中存在 DM 驱动、或仿真通过，都不能代替这项验证。

本页关注 DM4310 特有的数据和接线配置。CSV 契约、命令及报告格式见 [离线辨识](IDENTIFICATION.md)，C99 API 和生命周期见 [在线辨识](ONLINE_IDENTIFICATION.md)。

## 1. 先分清能收到什么

本库 [gimbal_dm4310_decode()](../src/gimbal_motor.c) 对应厂商标准八字节反馈。建议给“收到的报文”和“转换后的辨识样本”分别留记录，避免丢失原始证据。

| 本库字段 | 来自反馈报文 | 日志含义与限制 |
|---|---|---|
| `position_rad` | 16 位位置 | 模组输出轴坐标，rad；未做关节零位、方向、外部传动或连续角展开 |
| `velocity_rad_s` | 12 位速度 | 模组输出轴角速度，rad/s；不能直接替代运动底座下的 IMU 角速度 |
| `torque_nm` | 12 位力矩 | 建议原始日志命名为 `torque_reported_nm`，与标定后的关节力矩区分 |
| `state` | 首字节高 4 位 | 本库接受 1 为使能，0 为失能，其他状态拒绝参与控制；需核对电机固件 |
| `mos_temperature_c` | 第 6 字节，按 0 起算 | 驱动 MOS 平均温度，℃ |
| `rotor_temperature_c` | 第 7 字节 | 厂商定义为电机内部线圈平均温度，℃；字段名不代表另有转子温度传感器 |

字段布局、温度含义及状态来自厂商 [《调试助手使用说明书》V1.4，第 32–33 页](https://github.com/dmBots/damiao-document/blob/5e5a6932b8f013636415174c7433b9685ba24aa2/%E8%B0%83%E8%AF%95%E5%8A%A9%E6%89%8B%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E%E4%B9%A6%EF%BC%88%E8%BE%BE%E5%A6%99%E9%A9%B1%E5%8A%A8%E6%8E%A7%E5%88%B6%E5%8D%8F%E8%AE%AE%EF%BC%89V1.4.pdf)；字段名称和返回行为以本库 [gimbal_motor.h](../include/gimbal_motor.h) 为准。

**检查解码返回值后再使用数据。** 未使能或故障返回负值，本库只保留状态和温度，位置、速度、力矩已清零；这些零不是有效运动测量。错误 ID、错误 DLC 等返回的清零结构也不可填成有效样本。接收层还应先拒绝扩展帧、RTR 帧。

这份标准反馈没有独立的相电流、母线电压、加速度、重力角、硬件采样时间戳或专用限流标志。时间戳应由 MCU 在新帧接收时添加；重力角需要机构标定与姿态信息；加速度无需直接测量，本库使用积分方程。不能把 `state=1` 当作“执行器一定未限流”的证明。

## 2. 用实际电机配置建立 MIT 力矩通路

先保存一份调试助手读回的参数记录，并同步到 [gimbal_dm4310_config_t](../include/gimbal_motor.h)：

| 实际电机设置 | 本库配置或实验记录 |
|---|---|
| 型号、供电版本、固件版本、控制模式 | 写入实验元数据；本页采用 MIT |
| CAN ID | `command_id`，MIT 命令不加位置/速度模式的 ID 偏移 |
| MASTER_ID | `feedback_id`，即反馈帧仲裁 ID；另核对反馈首字节低 4 位与 `motor_id` |
| PMAX / VMAX / TMAX | `position_max_rad / velocity_max_rad_s / torque_max_nm` |
| 驱动内减速比、KT_OUT、齿轮系数、电流限制、通信超时 | 保留读回值，作为力矩比例和实验条件的来源 |
| 外部传动、安装方向、应用力矩限制 | `mechanics` 配置与独立机构记录 |

本库不读取或写入这些驱动参数。PMAX/VMAX/TMAX 同时影响报文的数值映射，不能只按“4310”型号猜值，也不能把 TMAX 编码量程当成可持续力矩；更改后应重新记录配置并开始新的数据集。MASTER_ID 是独立配置的反馈 ID，不能直接拿命令 ID 代填；多电机应配置可明确区分、无冲突的反馈路径。厂商参数定义见 [V1.4 第 10、39–40 页](https://github.com/dmBots/damiao-document/blob/5e5a6932b8f013636415174c7433b9685ba24aa2/%E8%B0%83%E8%AF%95%E5%8A%A9%E6%89%8B%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E%E4%B9%A6%EF%BC%88%E8%BE%BE%E5%A6%99%E9%A9%B1%E5%8A%A8%E6%8E%A7%E5%88%B6%E5%8D%8F%E8%AE%AE%EF%BC%89V1.4.pdf)。

MIT 在电机内部将位置项、速度项和 `t_ff` 相加形成参考力矩。本库 `gimbal_dm4310_pack_torque()` 把 `kp=kd=0`，让外部控制器通过 `t_ff` 给定力矩；**外部位置/速度控制与保护仍需运行**，这不意味着对未知负载持续施加开环恒定力矩。[厂商 MIT 模式说明，第 1–2 页](https://github.com/dmBots/damiao-document/blob/5e5a6932b8f013636415174c7433b9685ba24aa2/3.%20%E7%94%B5%E6%9C%BA%E4%B8%8A%E6%89%8B%E6%B5%81%E7%A8%8B%28%E4%B8%89%29-MIT%E6%A8%A1%E5%BC%8F%E8%AF%B4%E6%98%8E.pdf)

同时保留请求力矩、组包返回状态、提交发送的八字节、`applied_joint_nm` 和提交时刻。发送成功状态只有发送层实际记录后才可报告；软件提交不等于电机已执行。`applied_joint_nm` 仅是量化命令对应的名义关节力矩，不是电机反馈。12 位力矩映射的步长为 `2*TMAX/4095`，没有精确零码；零命令不等同失能。若改用非零 `kp/kd`，`t_ff` 就不再等于电机内部总参考力矩，需要记录全部给定和增益，不能混入当前纯力矩路径的命令比较。

## 3. 力矩、时间和轴坐标先核验

**力矩比例。** DM 回报的 torque 应作为驱动报告值，不能按独立应变式扭矩传感器读数使用。厂商控制图中，参考力矩通过 KT_OUT 换算为电流给定；KT_OUT 又与电机参数、内部减速比有关。这说明设置和比例会影响名义力矩，不能仅凭字段单位为 N·m 就宣布完成关节力矩标定。[厂商 MIT 模式说明，第 1 页](https://github.com/dmBots/damiao-document/blob/5e5a6932b8f013636415174c7433b9685ba24aa2/3.%20%E7%94%B5%E6%9C%BA%E4%B8%8A%E6%89%8B%E6%B5%81%E7%A8%8B%28%E4%B8%89%29-MIT%E6%A8%A1%E5%BC%8F%E8%AF%B4%E6%98%8E.pdf)

在相应工作范围内，用独立力矩参考，或已知载荷与力臂的实验核查正负方向、比例和零偏，并保留原始读数、温度与计算方法。静态加载会混入静摩擦、齿隙和预紧力，不能只凭单个悬挂点得出全量程标定；静态比例通过也不能证明快速运动中的反馈带宽和相位正确。比例未知时可先保存数据、分析命令与响应，暂不把它导出为已标定的物理惯量。

**轴坐标。** 设外部传动比 `n = 模组输出轴速度 / 关节速度`，方向 `s=±1`，常数传动时：

```text
q_joint     = s * (theta_module_continuous - theta_zero) / n
omega_joint = s * omega_module / n
```

这里不再乘 DM4310 内部减速比。力矩也要转换到同一关节侧，但实际传递效率、方向差异及损耗必须有依据；不要把猜定的效率当作反馈标定。解码器不做上述转换。连续 Yaw 要先核验该固件的位置回绕行为，并在采样连续的前提下展开；重启、清零或无法判断跨圈后要断开数据段。

Pitch 的 `q_g` 是相对重力方向的角度相位，不能直接拿电机位置代替。固定底座、固定几何关系下，所用位置与角速度必须描述同一坐标。折叠机构若传动比或等效惯量随动作明显变化，应先限定工作区间分别建模；不能用一个常数 `gear_ratio` 或一组参数覆盖整个折叠过程。

**时间。** 每个新 CAN 反馈新增本地接收时间和本地记录序号，保留总线/ID、DLC 和八字节原始数据，可用[通用 CAN 接收模板](templates/test_data/can_rx_raw.template.csv)；控制命令另记提交时刻。记录序号不是电机发出的序号，接收时刻也不是驱动内部采样时刻，需要核查传输、驱动反馈和 IMU 各自的延迟，统一到可解释的时基。读取同一缓存多次不算新反馈；丢帧、失能、故障、限幅或重启均应断窗。日志采样记录放在短快照中，导出交给低优先级任务，避免阻塞控制循环。

## 4. 固定构形采两份独立记录

先固定底座，锁定其他轴或保持其固定姿态，明确负载、折叠工作位、线缆状态、温度范围和机械边界。不同构形、负载或驱动参数使用不同 `configuration`，分别采集训练与验证数据。

| 记录内容 | 帮助区分的作用 | 要避免的情况 |
|---|---|---|
| 双向平滑往复，改变速度与加速度 | 惯量 J、粘性阻尼 B、库仑项 Fc | 长期匀速、只测单一方向、持续命令限幅 |
| Pitch 覆盖若干可用角度区间，并含双向慢速运动 | 重力 A/C 与摩擦的差异 | 只在一个静止角度停留；静摩擦可与重力混淆 |
| 同构形另录不同频率/相位或参考序列 | 检查未参与拟合的运动能否解释 | 复制训练文件，或将相邻行随机拆成训练/验证 |

幅度、速度、加速度与力矩上限由实际机械行程、温升、制动余量和已有控制稳定性决定，本页不提供可盲用的固定激励幅度。轨迹应由现有受限闭环执行，从已验证范围逐步扩展；不要通过直接持续增加 `t_ff` 来“凑激励”。

训练结束即固定候选参数，再评估独立记录。限幅/失能段保留在原始日志中，但标为不能用于辨识；不能只删除不利数据后宣称全部工况通过。更完整的记录要求见 [测试数据清单](TEST_DATA.md)。

## 5. 整理为离线候选，再评估在线使用

完成关节力矩标定、坐标核验和时间对齐后，才整理为离线工具的严格九列：

```csv
time_s,angle_rad,rate_rad_s,gravity_angle_rad,torque_nm,enabled,valid,saturated,segment
```

此处 `torque_nm` 是**经标定和时间对齐后的关节侧力矩估计**，不能直接把 `torque_reported_nm` 改列名充数。实测元数据使用 `data_kind=hardware`、`torque_source=calibrated_feedback`；这些声明需要独立依据。原始接收记录可保留缺失项；工具输入则要求各行数值有限、时间严格递增，无效占位行用 `valid=0`，禁止把缺测当成有效零值。

固定正值摩擦速度尺度 epsilon 后，工具从窗口积分辨识：

- **Yaw：** J、B、Fc；要求重力绕该轴的投影可忽略，倾斜 Yaw 不应直接套用。
- **Pitch：** 再加入 `A*sin(q_g)+C*cos(q_g)`；要求固定重力平面和适用的机构模型。

积分使用速度增量、角度增量及力矩/摩擦/重力的窗口积分，不直接差分加速度。按 [离线工具步骤](IDENTIFICATION.md#4-实验与输出) 设置独立验证误差门槛，检查秩、条件数、参数物理符号和 float32 导出结果。除窗口平均力矩误差，还要检查双向残差、不同角度/速度区间，以及新参数下的闭环跟踪、温升和限幅；手瞄、自瞄与模式切换分别验证。

参数始终是候选值：力矩比例在训练/验证中同时出错时，全部力矩参数仍可同比缩放而通过残差检查；一致的重力零位偏差也可由 A/C 吸收。闭环数据中的噪声相关性不会因采用积分最小二乘自动消失。

需要在 STM32 上继续估计时，每根轴、每个固定构形使用独立的 `gimbal_identification_t`，将合格的新反馈样本送入 `gimbal_identification_update()`。上层必须据实设置 `operating_conditions_valid`、`torque_calibrated`、`torque_time_aligned`，并检查本次 `window_updated/ready` 及诊断标志。模块不自动标定电机、不识别轴间耦合、不自动修改 SMC；采纳候选前仍需独立验证和可回退的参数版本。
