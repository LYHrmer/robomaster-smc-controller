# GM6020 云台：采集、标定与辨识

[文档导航](README.md) · [测试数据清单](TEST_DATA.md) · [电机协议](MOTOR_PROTOCOL.md) · [DM4310 专用指南](DM4310_IDENTIFICATION.md)

**本页只讲 GM6020。** 它的标准反馈提供电流原始计数，不直接给出已标定的 A 或 N·m；DM4310 的 MIT 力矩反馈请走上方另页。以下以已核对的双 GM6020 旧云台代码配置为例，Yaw 连续旋转，Pitch 为折叠机构。

按“确认电机模式 → 保存原始记录 → 标定与对齐 → 独立验证 → 可选在线”的顺序执行。本页和模板没有新增记录器，也不代表该云台已经通过实机辨识；只有姿态或原始电流记录时，可以先检查响应和通信，暂不能导出物理惯量。

## 1. 确认模式，再核对两轴接线

先在 RoboMaster Assistant 保存电机固件版本、工作模式和参数截图。GM6020 原生电流控制要求固件 `>=1.0.11.2`、Assistant `>=2.7`，并打开电流环开关；不能仅凭代码发送 `0x1FE` 判断实际已启用。[DJI 官方使用说明 v1.4，2023.10，第 6 页](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf)

| 旧工程示例 | CAN 总线 | 接收反馈 ID | 电流命令组及槽位 |
|---|---|---|---|
| Yaw | CAN1 | `0x206` | `0x1FE`，第二槽 |
| Pitch | CAN2 | `0x205` | `0x1FE`，第一槽 |

这是特定工程的配置，不是 GM6020 的固定接线要求。换电机、换总线或调 ID 后，应同步实验记录和接收过滤；共享命令组由一个发送者维护全部槽位。

本库以 `current_mode_confirmed=1` 表示应用已完成模式确认，不会自动升级固件或打开电流环。若仍使用原始电压模式，先阅读 [GM6020 两种模式的接入边界](MOTOR_PROTOCOL.md#gm6020明确区分两种模式)；本库没有替它实现 MCU 电流内环。

## 2. 区分反馈、命令与力矩

| 已有 GM6020 数据 | 可以怎样使用 | 不能怎样理解 |
|---|---|---|
| 编码器原码、旧 `GetAngle()` | 原码检查跨圈；旧驱动累计角单位 deg | 不是 IMU 姿态或已标定的折叠关节角 |
| `GetSpd()` | 协议转速 rpm，之后按机构坐标换算 | 不是运动底座下的惯性角速度 |
| `GetCurrent()` / `current_raw` | 有符号反馈计数，保留原值 | 不能直接标为 A 或 N·m |
| 温度原始字节 | 保留温度记录，比较实验条件 | 不是可推断全部保护状态的故障码 |
| `output_speed_[axis]`、最终 CAN 槽值 | 分别记录控制输出与实际软件提交值 | 名字中的 speed 不表示转速；提交也不证明执行成功 |
| 请求力矩 / `applied_joint_nm` | 分析算法请求、限幅与命令量化 | 都不是实测反馈力矩 |

**命令比例与反馈比例是两件事。** 官方给出的 `±16384 ↔ ±3 A` 是电流命令映射；所核对手册未给出反馈电流计数的安培换算比例，不能将命令比例直接套到 `current_raw`。[DJI 官方手册第 7 页](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf)

本库 [GM6020 解析接口](../include/gimbal_motor.h) 在 `feedback_current_a_per_count=0` 时只提供原始电流，`current_a_valid=0`。只有比例核验后才配置非零值；`current_a_valid=1` 也只表示按配置做了转换，不证明关节力矩已经标定。标准反馈没有独立的使能、内部限流或采样时刻字段，这些资格不能从保留字节猜测。

## 3. 先留这些原始记录

| 保存内容 | 空白模板 | 适用范围 |
|---|---|---|

| 实际提交的四槽命令 | [can_tx.template.csv](templates/test_data/can_tx.template.csv) | **GM6020 专用**：在各发送分支记录，包含停止后的零命令 |
| 只保存 CAN 接收字节 | [can_rx_raw.template.csv](templates/test_data/can_rx_raw.template.csv) | 两种电机通用原帧格式，解码规则仍按型号分别处理 |
| 目标、姿态、陀螺、模式与原始输出 | [mcu_control_existing.template.csv](templates/test_data/mcu_control_existing.template.csv) | 旧云台控制快照，需新增记录点和导出 |
| 现有 USB 数据 | [usb_existing.template.csv](templates/test_data/usb_existing.template.csv) | 可先保存；不是完整控制/辨识日志 |
| 固件、参数、构形与采集能力 | [run.template.json](templates/test_data/run.template.json) | 人工填写，当前默认双 GM6020；不是工具 `--metadata` |

模板仅提供字段约定，旧固件不会自动输出这些表。CAN/控制任务只复制短快照，导出由低优先级任务完成；具体字段来源和已有 USB 的角速度、四元数限制见 [GM6020 旧工程数据清单](TEST_DATA.md#1-gm6020-旧工程现在能得到什么)。

每份流记录本地时间和新增的日志序号，说明取值位置。模板 `*_tick_ms` 是拟新增的 MCU 软件记录时刻，不是电机内部采样时间；现有 USB 包没有 MCU 时间戳。保存原始事件中的同毫秒多帧、丢帧和重启，不能把它们强行当成均匀采样。

## 4. 补齐反馈力矩和同坐标时间

1. **核验电流反馈。** 取得对应固件的反馈定义，核查零位、正负方向和比例，保存原始帧与依据。若使用独立电流参考，应确认测量量与驱动的转矩电流含义一致，不能直接用电源输入电流代替。
2. **核验关节力矩。** 再核查转矩常数、外部传动和损耗，利用独立力矩参考或已知载荷/力臂实验检查实际关系。覆盖正反向和不同载荷；单点静态平衡会混入静摩擦，不能据此证明整个运动范围的力矩准确性。
3. **统一轴坐标。** 记录电机方向、编码器零位、外部传动及 IMU 安装。用于辨识的角度与角速度必须对应同一关节坐标，角度转换到 rad；机体系陀螺不能在任意姿态下直接当作欧拉角导数。
4. **核验时间。** 保留 CAN、INS、控制和发送各自的更新时间，检查反馈延迟、时基关系及缓存陈旧。重复读取同一缓存不算新反馈；时间同步声明要有测量依据。

完成这四步后，才生成“已标定、已对齐的关节侧力矩估计”。比例未知时，小拟合残差不能证明物理惯量正确；两份数据使用同一个错误比例，全部力矩参数仍可能同比缩放。

## 5. 按轴和工作位分别采集

先固定底座和其他轴，保存负载、机械范围、限幅与温度条件。在现有稳定闭环允许的范围内做双向平滑运动，包含不同速度和加速度；幅度由实际行程、制动余量和温升决定，本页不提供固定激励数值。

| 对象 | 本次需要确认 | 当前模型边界 |
|---|---|---|
| 连续 Yaw | 连续角、跨圈处理、角速度坐标与方向 | 三参数模型辨识 J/B/Fc，假定绕该轴的重力投影可忽略；倾斜轴另行评估 |
| 折叠 Pitch 的固定工作位 | 重力相位、负载、上下行及不同可用角度区间 | 再辨识重力 A/C；不能只在一个静止角度区分重力与静摩擦 |
| 切换折叠工作位或负载 | 另建构形编号、照片和参数记录 | 分别辨识，不把折叠运动或多轴联动视为已验证 |

没有折叠角传感器时可记录人工工作位和几何标定，不虚构第二关节反馈。若一个工作区间内传动关系或等效惯量已明显变化，应进一步限定范围或换模型。

同一构形另录一份不同参考频率、相位或序列的独立验证实验。训练和验证不能只是相邻行随机拆分，也不能靠换文件名制造独立性。原始限幅、停止、故障、缺测段照常保存，在分析时按规则排除并断窗。

## 6. 先验证离线候选，再决定是否在线

按 [离线数据契约](IDENTIFICATION.md#3-最小侵入的日志接入) 整理一轴一构形的九列 CSV 和元数据，再按 [实验与输出步骤](IDENTIFICATION.md#4-实验与输出) 运行工具。公式、窗口设置、命令行和导出字段共用该页，不另设一套 GM6020 格式。

只有独立完成标定和对齐，才能声明 `calibrated_feedback` 与时间已对齐。工具输入要求有限值、严格递增时间及明确无效/饱和标志；`segment` 用于断窗，不会自动把同一文件的不同构形分别拟合。所用积分方法直接利用角速度增量，无需把旧工程未更新的 `INS.dGyro` 当作实测加速度。

检查候选物理符号、数据秩、条件数、独立验证误差与 float32 导出结果。再在同一参数版本下分别验证手瞄、自瞄、模式切换、Yaw 跨圈和 Pitch 固定工作位的跟踪、温升、限幅。保存原始日志、转换脚本、报告和回退参数；通过窗口平均残差门槛不是实机闭环通过。

需要在线计算时，按 [在线辨识接入](ONLINE_IDENTIFICATION.md#2-如何接入已有工程) 给每轴、每个固定构形分配独立实例，依据真实条件设置 `torque_calibrated`、`torque_time_aligned` 和 `operating_conditions_valid`。本次 `window_updated/ready` 只表示估计更新及数据资格，不授权自动采纳。

现有双 GM6020 旧工程的 SMC 移植版尚未接入 RLS。在线模块不会替代电流/力矩标定，也不会自动改写 SMC；新增日志、模型采纳与回退仍由应用层实现。完整验证边界见 [在线验证说明](ONLINE_IDENTIFICATION.md#6-验证与适用范围)。
